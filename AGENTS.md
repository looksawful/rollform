# Правила работы с ROLLFORM

- Перед изменениями прочитай [README.md](README.md) и затронутые файлы. Текущее поведение определяют исходники и тесты.
- `main` — единственная рабочая ветка; CI публикует Pages напрямую через workflow. `gh-pages` — историческая ветка, её не редактировать. Отдельную ветку создавай только по просьбе пользователя.
- Сохраняй утверждённые тексты и заглушки: Hero «Заголовок», существующий текст, кнопка «Создать случайный кубик». Меняй их только по явному запросу.
- 3D-превью вращаются автоматически до первого взаимодействия; затем пользователь вращает перетаскиванием и немного масштабирует колёсиком, без видимых контролов (кроме метки 3D-превью вне Hero). Сохраняй `prefers-reduced-motion`. Одно дерево маршрутов с переключением светлой/тёмной темы в шапке.
- Светлая и тёмная версии используют одни компоненты. Не добавляй неподтверждённые сведения о товаре, наличии, материалах, сроках или контактах.
- Прототип не принимает оплату и не отправляет заявки; не представляй его как работающий магазин.
- После изменения кода выполни `npm test`, `npm run typecheck`, `npm run build` и проверь затронутые страницы в браузере. Непроверенное отмечай явно.
- История решений, QA и передача работ: [Issue #5](https://github.com/looksawful/rollform-internal/issues/5) и связанная задача Asana. Дополняй существующие записи, не создавай журналы исследований в README/AGENTS/docs.
